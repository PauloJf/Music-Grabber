# 1.0.0 readiness

What stands between 0.1.0 and a release BPM Tagger can point at. "Stable" is defined in
`extraction.md` section 5.2: Music Grabber >= 1.0.0, the import tool verified on a real migrated
database, the intake flow verified end to end against a running BPM Tagger.

## Verified (2026-10-23)

**Import, on a copy of a real BPM Tagger 2.18.2 database** (read-only source, hashes unchanged
after every run; the library was a stand-in of tiny tagged files built from the source `tracks`
table, so matching ran for real but the audio did not):

| | source | imported |
|---|---|---|
| Spotify playlists (+2 local, never moved) | 4 | 4 |
| their playlist tracks (+40 local-playlist rows, never moved) | 404 | 404 |
| `grab_queue` (38 awaiting_user, 5 done) | 43 | 43, same statuses |
| `grab_candidates` / `grab_events` | 71 / 268 | 71 / 268 |
| awaiting_user items that have candidates | 11 of 38 | 11 of 38 |
| `tracks WHERE managed=1`, not deleted (72 deleted skipped) | 863 | 863 ledger rows, all paths library-relative |
| Spotify token (`--include-tokens`) | 1 | 1, identical; absent without the flag |
| `grabbed_total` | 936 | 936 |

A second run without `--merge` is refused; with `--merge` everything is skipped as already
present. `foreign_key_check` and `integrity_check` are clean. After import `status` shows
"403 have, 0 missing, 1 queued"; a real index scan of the stand-in library and a re-match gives
the same per-playlist counts, with no new queue items.

**Intake end to end** (`bpm-tagger:nograb` in watch mode and the Music Grabber image sharing one
volume; a fake provider fed generated click-track audio, so real ffmpeg, tagging, placement and
ledger ran, with no network): five files, including two into brand-new folders, were each
analysed by BPM Tagger exactly once with the right BPM (124, 100, 140, 90 and, with
`ANALYSIS_WAIT_SECONDS`, 128 reported back by Music Grabber). The hidden `.mg_part_*.part` file was
visible in the intake folder and ignored; no partial file ever appeared under a final name.

## Found and fixed here

- An index with no files turned every watched track into "missing" and queued them all (a wrong
  mount after a migration would have started hundreds of downloads). Sync now holds back automatic
  queueing in that state on an install that has grabbed or imported before.
- `import-env` copied BPM Tagger's `ui_public_url` into Music Grabber's `UI_PUBLIC_URL`.
- `import-bpm-tagger` silently kept absolute paths when `--source-music-dir` did not match
  (easy to trigger: Git Bash on Windows rewrites `/music`). It now warns.
- No CLI for "queue missing" (only the web UI had it); added `playlist queue-missing ID`.
- CI never built the Docker image (it was first built at release time); it does now, unpushed.
